## Exercise 01 — a value or the errors that stopped it *(from the answer key)*

| piece | idea |
| --- | --- |
| `Validated[+E, +A]` | `Valid(42)` is a `Validated[Nothing, Int]`; covariance makes it fit any error type |

## Exercise 02 — combine two results, keep both errors *(from the answer key)*

| piece | idea |
| --- | --- |
| `Semigroup` instances in its companion | the one companion in the implicit scope this code owns |
| `map2[E: Semigroup]` | an error type that cannot combine (`Boolean`) is a compile error |
| `e1.combine(e2)` in that order | the errors keep the order of the checks |

## Exercise 03 — `Applicative`, for `Option` and for `Validated` *(from the answer key)*

| piece | idea |
| --- | --- |
| `[A] =>> Validated[E, A]` | fixes the error type, leaving the one-hole shape `F[_]` asks for |
| `given [E: Semigroup] => Applicative[...]` | conditional, so any `E` with a `Semigroup` works, and no other |
| `map` from `map2` and `pure` | an applicative is a functor for free |

## Exercise 04 — `traverse`, written once

| piece | idea |
| --- | --- |
| `map2(acc, f(a))` | the *position* of the arguments decides the order of the errors; the function only handles the values |
| no `_.reverse` at the end | `map` never reaches an `Invalid`, so it can fix the values' order but never the errors' |
| `foldRight` with `map2(f(a), rest)(_ :: _)` | the final version: no `reverse`, no quadratic `:+` |
| `traverse(forms)(signUp)` | `traverse` validates nothing itself; the function it applies does |

**Stuck on:** I reversed the errors with a left-to-right loop that consed onto
the accumulator. Then `signUpAll` built the `User` directly instead of calling
