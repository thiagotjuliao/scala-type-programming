# Capítulo 02 — Higher-kinded types & type lambdas

Minhas notas sobre o que cada exercício ensinou. Reconstruídas em 2026-10-13 a
partir da sessão de 2026-09-23 (exercício 01) e, para os outros, do Scaladoc
do gabarito.

## Exercício 01 — declarar cada parâmetro no kind que os membros pedem

| peça | ideia |
| --- | --- |
| `Mappable[F[_]]`, `BiMappable[F[_, _]]` | o kind sai de como o membro aplica o parâmetro: `F[A]` é um buraco, `F[A, B]` são dois |
| `Instances[TC[_[_]]]` | `forList` escreve `TC[List]`, então `TC` recebe um *construtor* de tipo: os underscores ficam aninhados |
| `forList: TC[List]` | o tipo de retorno sai daquilo a que o parâmetro é aplicado |

**Onde travei:** escrevi primeiro `Instances[F[_]]`, o mesmo kind de
`Mappable`, que aceitava `List` e recusava `Mappable`. Também esbarrei num
problema do build: a spec era julgada contra um stub antigo em cache, porque
os snippets só citam o exercício dentro de strings (corrigido no `build.sbt`
com o carimbo dos snippets).

## Exercício 02 — aplicar `Either` parcialmente com um type lambda *(do gabarito)*

| peça | ideia |
| --- | --- |
| `type ErrorOr[E] = [X] =>> Either[E, X]` | curried de propósito: `ErrorOr[String]` é um construtor completo, de um buraco |
| a inferência encontra | o compilador alinha o argumento com o *último* parâmetro e toma o resto como construtor |

## Exercício 03 — um functor do outro lado *(do gabarito)*

| peça | ideia |
| --- | --- |
| `type OnLeft[E] = [X] =>> Either[X, E]` | válido, mas a inferência nunca o encontra: só o último buraco é tentado |
| `inc[OnLeft[String]](...)` | a instância precisa ser nomeada na chamada — por isso as bibliotecas põem o parâmetro que varia por último |

## Exercício 04 — compor dois construtores de tipo *(do gabarito)*

| peça | ideia |
| --- | --- |
| `Compose[F, G] = [X] =>> F[G[X]]` | uma função de tipos sobre funções de tipos; a ordem é a definição inteira |
| um único functor `composed` | escrito uma vez para todo par: o `map` de fora visita cada `G[A]`, o de dentro cada `A` |
