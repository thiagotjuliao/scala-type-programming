# Chapter 02 — Higher-kinded types & type lambdas

My notes on what each exercise taught. Reconstructed on 2026-10-13 from the
session of 2026-09-23 (exercise 01) and, for the rest, from the answer key's
scaladoc.

## Exercise 01 — declare each parameter at the kind its members need

| piece | idea |
| --- | --- |
| `Mappable[F[_]]`, `BiMappable[F[_, _]]` | the kind is read off how the member applies the parameter: `F[A]` is one hole, `F[A, B]` two |
| `Instances[TC[_[_]]]` | `forList` writes `TC[List]`, so `TC` takes a type *constructor*: the underscores nest |
| `forList: TC[List]` | the return type follows from what the parameter is applied to |

**Stuck on:** I first wrote `Instances[F[_]]` — the same kind as `Mappable`,
so it accepted `List` and rejected `Mappable`. Also hit a build issue: the spec
was judged against a cached old stub, since snippets only mention the

## Exercise 02 — partially apply `Either` with a type lambda *(from the answer key)*

| piece | idea |
| --- | --- |
| `type ErrorOr[E] = [X] =>> Either[E, X]` | curried on purpose: `ErrorOr[String]` is a complete one-hole constructor |
| inference finds it | the compiler lines the argument up with the *last* parameter and takes the rest as the constructor |

## Exercise 03 — a functor over the other side *(from the answer key)*

| piece | idea |
| --- | --- |
| `type OnLeft[E] = [X] =>> Either[X, E]` | valid, but inference never finds it: only the last hole is tried |
| `inc[OnLeft[String]](...)` | the instance must be named at the call — why libraries put the varying parameter last |

## Exercise 04 — compose two type constructors *(from the answer key)*

| piece | idea |
| --- | --- |
| `Compose[F, G] = [X] =>> F[G[X]]` | a type-level function over type-level functions; the order is the whole definition |
| one `composed` functor | written once for every pair: outer `map` visits each `G[A]`, inner `map` each `A` |
