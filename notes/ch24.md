# Chapter 24 — Derived JSON codec

My notes on what each exercise taught. Reconstructed on 2026-10-13 from the
sessions of 2026-10-08 to 2026-10-12.

## Exercise 01 — `Encoder.derived`

| piece | idea |
| --- | --- |
| name, encoder, value | the first two come from the `Mirror` while compiling; the value only exists at runtime, via `productIterator` |
| `summonFrom`: a ready encoder before the `Mirror` | `Option` and `List` have mirrors too; deriving first would encode `Some("ada")` as an object with `"type": "Some"` |
| `lazyZip`, not `for` | three generators make every combination |
| encoders by name, no `val` in `derived` | a recursive type's encoder needs itself; evaluated at creation it reads itself before it exists — that hung the sbt server |
| `lazy val encs` inside the `def` | computed once, on the first `encode` |
| `encoderProduct` / `encoderSum` as ordinary `def`s | the lambda's anonymous class would be copied into every derivation |
| `ordinal` | the case's position picks the name and the encoder by the same index |
| `match` on the case's `JObject` | `Json` does not promise an object, so `"type"` can only be prepended after matching |

## Exercise 02 — `Decoder.derived`

| piece | idea |
| --- | --- |
| `fromProduct`, not `fromTuple` | values built at runtime as `List[Any]` only make a `Tuple`; `fromTuple` wants the exact type |
| a missing field decodes `JNull` | the derivation does not know whether a field is optional; the field's decoder does |
| `"missing"` instead of the decoder's message | for an absent field, "expected a whole number" misleads |
| `label :: e.path` | the path is built inside out; each level prepends its own name |
| `foldRight` with a `for` over `Either` | a `for` has a fixed number of `<-`; the fold combines one field with the rest, stopping at the first error |
| `lazy val` outside `json => ...` | inside the function it is recomputed on every `decode` |
| the case's position from `"type"` | there is no value to call `ordinal` on yet |
| the whole object to the case's decoder | the product decoder only looks up its own field names, so `"type"` is ignored |

**Stuck on:** `:+` instead of prepend for the path; a trailing `???` after the
`inline match` that became the result; and `"unknown case Triangle"` written
as a constant — the spec tested only that one name.

## Exercise 03 — a compile error that names the type and the field

| piece | idea |
| --- | --- |
| `@implicitNotFound` on the trait | a plain `summon[Encoder[Instant]]` looks the message up on the type it searches for |
| `case _ => error(...)` in `summonFrom` | a case that finds nothing simply does not match — no message; without a last case, the error is the generic one about `summonFrom` |
| `MirroredLabel` vs `MirroredElemLabels` | the type's own name vs its fields' names |
| `instances[T, Ts, Ls]` matching `(Ts, Ls)` | `instance` only knows `H` (here `Instant`); the parent's name and the field's name are carried down the recursion as literal types |
| `"..." + constValue[T] + "..."` | `error` needs a constant; `constValue` of a literal type is one, and the concatenation is folded |
| `Meeting` reports `Event` | `Event` is derived on the way, as a field; the error points where the expansion stopped |

**Stuck on:** I first thought the trait's `@implicitNotFound` would show up
inside the derivation. And a missing space: `fieldathas` — the spec compares
the start of the message exactly.
