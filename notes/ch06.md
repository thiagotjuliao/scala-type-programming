# Chapter 06 — Type classes, givens & implicit search

My notes on what each exercise taught. Reconstructed on 2026-10-13 from the
session of 2026-09-25 (exercise 04) and, for the others, from the answer key's
scaladoc.

## Exercise 01 — a Show for everything built from showable parts *(from the answer key)*

| piece | idea |
| --- | --- |
| `[A: Show] => Show[List[A]]` | a conditional instance: a rule with a premise, chained by the search |
| instances in the companion | in the implicit scope of every `Show[...]` search, with no import |
| `import X.*` | does not bring givens in; `import X.given` does |

## Exercise 02 — an ordering found everywhere, and one on request *(from the answer key)*

| piece | idea |
| --- | --- |
| `Ordering.by(v => (major, minor, patch))` | reuse the library's tuple ordering instead of comparing by hand |
| `NewestFirst` imported | the lexical scope is searched before the implicit scope, so the two never meet |

## Exercise 03 — two rules apply; say which one wins *(from the answer key)*

| piece | idea |
| --- | --- |
| low-priority trait | a given in an object wins over one in a trait the object extends |
| same shape, different premises | side by side they are *"Ambiguous given instances"* |

## Exercise 04 — a result type computed by the search

| piece | idea |
| --- | --- |
| `add(a, b)(using c: Add[A, B]): c.Out` | the result type depends on the instance the search picked |
| instances declared as `Aux[A, B, O]` | declared as plain `Add[Int, Int]`, the instance forgets its `Out` |
| `given pair[A, B, C, D, O1, O2](using first: Aux[A, B, O1], second: Aux[C, D, O2]): Aux[(A, C), (B, D), (O1, O2)]` | the premises fix `O1` and `O2`; nested pairs recurse through the same rule |

**Stuck on:** munit's *"Can't compare these two types: given_Add_Int_Int.Out
and Int"* — the instance had lost its `Out` because I declared it as `Add`.
For the pair rule: `A` pairs with `B` and `C` with `D` (opposite sides), not
`A` with `C`.

**Learned on the way:** a conditional given can be written with `using`
(`given name[T](using ...): Result`) or with the newer arrow syntax
(`given [T] => (s: Show[T]) => Result`); the arrow one is preferred since
Scala 3.6 (SIP-64).
