# Chapter 04 — Literal, singleton, union & intersection types

My notes on what each exercise taught. Reconstructed on 2026-10-13. This
chapter was solved without a tutoring session, so everything here comes from
the answer key's scaladoc.

## Exercise 01 — make a type out of three values

| piece | idea |
| --- | --- |
| `type Status = 200 \| 404 \| 500` | a union of literal types has exactly three inhabitants |
| `final val Ok = 200` | an unannotated `val` widens to `Int`; `final val` keeps the literal type |
| no default case in `describe` | a match on a union of literals is checked for exhaustiveness |

## Exercise 02 — keep the caller's type through a chain

| piece | idea |
| --- | --- |
| `def header(...): this.type` | returns the receiver's singleton type, so a subclass keeps its own methods down the chain |
| `withHeaders(r: Request): r.type` | the same from outside: the parameter is a stable path |

## Exercise 03 — a result that lists every way it can fail

| piece | idea |
| --- | --- |
| `Int \| Missing \| Malformed \| OutOfRange` | errors with no common parent, in one type, with no sealed hierarchy |
| `explain` with a `match` | a match over a union is checked for exhaustiveness |
| declare `PortResult` | inferred, the union keeps the nested shape it was assembled in |

## Exercise 04 — ask for two capabilities at once

| piece | idea |
| --- | --- |
| `stamp(env: Logger & Clock)` | an intersection accepts anything that is both, declared in advance or not |
| `combine` as an anonymous class with both parents | each member delegates to the value that provides it |
