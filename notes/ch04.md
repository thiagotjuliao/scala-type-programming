Minhas notas sobre o que cada exercício ensinou. Reconstruídas em 2026-10-13.

## Exercício 01 — um tipo feito de três valores

| peça | ideia |
| --- | --- |
| `type Status = 200 \| 404 \| 500` | uma união de tipos literais tem exatamente três habitantes |
| `final val Ok = 200` | um `val` sem anotação alarga para `Int`; `final val` mantém o tipo literal |
| sem caso default no `describe` | um match sobre uma união de literais é verificado quanto à exaustividade |

## Exercício 02 — manter o tipo de quem chama ao longo de uma cadeia

| peça | ideia |
| --- | --- |
| `def header(...): this.type` | devolve o tipo singleton do receptor, então uma subclasse mantém os próprios métodos na cadeia |
| `withHeaders(r: Request): r.type` | o mesmo, de fora: o parâmetro é um caminho estável |

## Exercício 03 — um resultado que lista todas as formas de falhar

| peça | ideia |
| --- | --- |
| `Int \| Missing \| Malformed \| OutOfRange` | erros sem pai em comum num só tipo, sem hierarquia selada |
| `explain` com um `match` | um match sobre uma união é verificado quanto à exaustividade |
| declarar `PortResult` | inferida, a união mantém a forma aninhada em que foi montada |

## Exercício 04 — pedir duas capacidades de uma vez

| peça | ideia |
| --- | --- |
| `stamp(env: Logger & Clock)` | uma interseção aceita qualquer coisa que seja as duas, declarada antes ou não |
| `combine` como classe anônima com os dois pais | cada membro delega ao valor que o fornece |
