## Exercício 01 — um caminho cujo tipo lista o que captura

| peça | ideia |
| --- | --- |
| `/[A](capture: Capture[A]): Path[Tuple.Append[In, A]]` | a captura põe `A` no fim de `In`; no início (`A *: In`) os tipos sairiam invertidos, `(String, Int)` em vez de `(Int, String)` |
| `/(literal: String): Path[In]` | um literal não acrescenta nada à tupla |
| o tipo de `post` não é escrito em lugar nenhum | sai de quatro chamadas de `/`, cada uma calculando um `Tuple.Append` |
| `in.toList: List[Union[In]]` | dentro de `render`, `In` é abstrato e `Union[In]` não reduz, mas tudo é `Any`, que é o que `Capture.show` aceita |
| `foldLeft` carregando os valores que sobram | não dá `zip`: o literal não consome valor, a captura consome o próximo |
| `foldLeft` + `::` + `.reverse` | `foldRight` casaria a última captura com o primeiro valor: `ClassCastException` no cast de `show` |
| `mkString("/", "/", "")` | `/` entre as partes, não depois de cada uma; dá `"/"` para o root |
| `throw AssertionError(...)` no caso impossível | invariante minha, não erro de quem chama (`assert` para mim, `require` para o chamador); `???` diria "falta implementar" |
| `split("/").filter(_.nonEmpty)` | o `split` do Java mantém o `""` do início e descarta os do fim; `.tail` quebra em `"/"` (lista vazia) |
| `segments.length == parts.length` antes do `zip` | o `zip` corta no menor: `"/users/42"` casaria com `userPosts` |
| literal → `Some(ins)`, captura → `c.read(s).map(_ :: ins)` | só as capturas viram valores; o literal só confere |
| `Tuple.fromArray(...).asInstanceOf[In]` | `fromArray` devolve `Tuple`; o cast vale para a tupla montada, não para cada elemento, e só é seguro se a ordem estiver certa |

**Onde travei:** não achei `toList` porque procurei no `object Tuple` (os
métodos de conversão ficam no `trait`). Não vi o `""` inicial do `split`.
Coloquei os literais na lista de valores do `parse` e esqueci o `.reverse`
ali. Com duas capturas o tipo dizia `(Int, String)` e o valor era
`("hello", 42)`, e só o `assertEquals` pegou.
