Minhas notas sobre o que cada exercício ensinou. Reconstruídas em 2026-10-13 a

## Exercício 01 — dar a cada grafo o seu próprio tipo de nó *(do gabarito)*

| peça | ideia |
| --- | --- |
| `Node` dentro de `Graph` | uma classe aninhada é membro de cada instância: `g1.Node` e `g2.Node` são dois tipos |
| `link(g: Graph)(a: g.Node, b: g.Node)` | um parâmetro é um caminho estável, então uma lista seguinte pode selecionar através dele |
| `Graph#Node` | o tipo para *juntar* nós, nunca para *usá-los* |

## Exercício 02 — tipar um store de configurações pela chave *(do gabarito)*

| peça | ideia |
| --- | --- |
| `get(k: Key): Option[k.Value]` | o tipo de retorno sai da chave passada |
| um cast dentro do `get` | o único lugar em que o sistema de tipos é aceito na confiança |

## Exercício 03 — guardar a dependência num valor de função

| peça | ideia |
| --- | --- |
| `(k: Key) => String => Option[k.Value]` | dar nome ao parâmetro num tipo de função deixa o resultado depender dele |
| a anotação era o bug | `Key => String => Option[?]` prometia menos que o corpo e jogava a dependência fora |
| um leitor que ignora a chave é recusado | `Option[Int]` não é um `Option[k.Value]` para um `k` qualquer |

**Onde travei:** os dois corpos estavam certos e só os tipos errados —
`Option[?]` em todo lugar. A dica que destravou: dar nome ao parâmetro, como no
`reader` do walkthrough.

## Exercício 04 — consertar três chaves que esqueceram o tipo

| peça | ideia |
| --- | --- |
| `port: Key` → `Key.Aux[Int]` | anotar com o trait esquece o refinamento |
| `def host` → `val host` | um `def` não é caminho estável: *"not a valid type prefix, since it is not an immutable path"* |
| `keyOf(...): Key.Aux[V]` | o mesmo alargamento do `port`, num tipo de retorno; o `V` continua inferido pelo parser |

**Perguntei:** por que o `def` perde o tipo? Não perde — `host.parse(...)`
compilava. O que o `def` não pode é ser *caminho* para `host.Value`, porque cada
chamada pode devolver uma chave diferente. Guardar o resultado num `val`
devolve o caminho, a mesma saída do `fresh().node(...)` do walkthrough.
