# Chapter 03 — Path-dependent & dependent function types

My notes on what each exercise taught. Reconstructed on 2026-10-13 from the
session of 2026-09-24 (exercises 03 and 04) and, for the others, from the
answer key's scaladoc.

## Exercise 01 — give each graph a node type of its own *(from the answer key)*

| piece | idea |
| --- | --- |
| `Node` inside `Graph` | a nested class is a member of each instance: `g1.Node` and `g2.Node` are two types |
| `link(g: Graph)(a: g.Node, b: g.Node)` | a parameter is a stable path, so a later list can select through it |
| `Graph#Node` | the type to *collect* nodes under, never the one to *use* them at |

## Exercise 02 — type a settings store by its key *(from the answer key)*

| piece | idea |
| --- | --- |
| `get(k: Key): Option[k.Value]` | the result type is read off the key passed in |
| one cast inside `get` | the single place the type system is taken on trust |

## Exercise 03 — keep the dependency in a function value

| piece | idea |
| --- | --- |
| `(k: Key) => String => Option[k.Value]` | naming the parameter in a function type lets the result depend on it |
| the ascription was the bug | `Key => String => Option[?]` promised less than the body, and threw the dependency away |
| a reader that ignores its key is refused | `Option[Int]` is not an `Option[k.Value]` for an arbitrary `k` |

**Stuck on:** I had both bodies right and only the types wrong — `Option[?]`
everywhere. The hint that unlocked it: name the parameter, like the
walkthrough's `reader`.

## Exercise 04 — repair three keys that forgot their type

| piece | idea |
| --- | --- |
| `port: Key` → `Key.Aux[Int]` | an ascription to the trait forgets the refinement |
| `def host` → `val host` | a `def` is not a stable path: *"not a valid type prefix, since it is not an immutable path"* |
| `keyOf(...): Key.Aux[V]` | the same widening as `port`, in a result type; `V` is still inferred from the parser |

**Asked:** why does `def` lose the type? It does not — `host.parse(...)` still
compiled. What a `def` cannot do is be a *path* for `host.Value`, because each
call may return a different key. Binding the result to a `val` gives the path
back, the same fix as `fresh().node(...)` in the walkthrough.
