# Chapter 07 — Match types

My notes on what each exercise taught. Reconstructed on 2026-10-13 from the
session of 2026-09-25 (exercises 01, 03, 04) and, for exercise 02, from the
answer key's scaladoc.

## Exercise 01 — take one layer off a type

| piece | idea |
| --- | --- |
| `case Option[a] => a` | the test is subtyping, so `Some` and `Right` need no case of their own |
| `Either[?, a]` | a wildcard where the binder would go unused |
| `case _ => X` last | first, it would match everything; last, it is reached only after the others are proved disjoint |

## Exercise 02 — take every layer off a type *(from the answer key)*

| piece | idea |
| --- | --- |
| `case Option[a] => Leaf[a]` | recurse through the type itself, not through exercise 01's `Unwrap` |
| the catch-all is the base case | outside its domain a match type does not fail, it just never reduces |

## Exercise 03 — a result type computed from the argument's

| piece | idea |
| --- | --- |
| one typed pattern per case, same order | only a value match that mirrors the match type lets each branch be checked against the reduced type |
| `s.headOption` | the "is it empty" lives inside the branch, not in extra cases |

**Stuck on:** I wrote six value/extractor patterns (`""`, `Nil`, `None`,
`h :: _`...) — every branch was then checked against a stuck `First[X]`.

## Exercise 04 — units that cancel

| piece | idea |
| --- | --- |
| `(U, V) match` | a pair as scrutinee compares both units at once |
| `c match { case b => a }` | inside the result, `b` is the type the outer pattern bound: that is how two types are compared |
| an inner `case _` | once an outer case is chosen, the outer catch-all is no longer in play; the inner match needs its own "otherwise" |

**Stuck on:** `speed * distance` stayed `Meters match { case Seconds => Meters }`
— the inner match had no fallback, and the compiler does not go back to try
the next outer case.
