# Capítulo 22 — Typed builders and protocols

Minhas notas sobre o que cada exercício ensinou. Reconstruídas em 2026-10-13 a
partir da sessão de 2026-10-06.

## Exercício 01 — um builder com schema

| peça | ideia |
| --- | --- |
| `K <: String & Singleton` | sem `Singleton`, `"age"` alarga para `String`; match types testam por subtipagem, então a busca para no primeiro par |
| `(key: K)` antes do `using` | as listas de parâmetros são resolvidas da esquerda para a direita; com a evidência primeiro, `K` ainda é só o seu limite |
| `(n *: v *: EmptyTuple) *: t` | um par é `n *: v *: EmptyTuple`; sem o `EmptyTuple`, `v` pega a cauda do par |
| `Contains` sem usar `Lookup` | o estado do builder é uma tupla de chaves, não de pares; cada match type percorre a forma que recebe |
| `case EmptyTuple => false` | sem ele o match type fica preso justamente na tupla vazia, onde todo builder começa |
| `value: Lookup[Schema, K]` | uma chave errada dá `Nothing`, e nenhum valor tem tipo `Nothing` |

**Aprendi (e entrou nos pitfalls do capítulo 07):** um match type cujo
scrutinee é `Nothing` não reduz.

## Exercício 02 — `build` só quando completo

| peça | ideia |
| --- | --- |
| `AllIn[Required, S]`, nessa ordem | `R` é o que precisa estar contido; invertido, o teste sem `age` passava por coincidência |
| `@implicitNotFound` num trait meu | no `=:=` dentro de um `using`, o texto só virava parte do tipo impresso |
| `given ... => (AllIn[...] =:= true) => Completed[S]` | antes da última seta, a condição; depois dela, o que o given fornece |
| `new Completed[S] {}` | trait não tem construtor: classe anônima, ou uma `class` |

**Onde travei:** a seta do given estava virada. E o `contains` da spec aceitou
a minha primeira mensagem, que não *começava* com o texto — o curso agora tem
o `assertTypeErrorStartsWith`.

## Exercício 03 — uma conexão que segue o protocolo

| peça | ideia |
| --- | --- |
| `send(message: Tuple.Head[Left])` | o tipo da mensagem é calculado a partir do estado |
| `Conn[Tuple.Append[Sent, Tuple.Head[Left]], Tuple.Tail[Left]]` | tipo e valor crescem juntos; `sent :* message` é o valor cujo tipo é `Append` |
| uma mensagem depois da última | `Tuple.Head[EmptyTuple]` fica preso, e nenhum valor tem um tipo preso |
| `close(conn: Conn[P, EmptyTuple]): P` | o tipo do parâmetro já é a regra; `sent` reduz para `P`, sem cast |
| `Conn` dentro de `Server` | `server.Conn` e `other.Conn` são diferentes mesmo com o mesmo `P` |
| construtor `private[Server]` | só `private` esconderia o construtor também do `connect()` |

**Onde travei:** `.Head` não é sintaxe de tipo — é `Tuple.Head[Left]`. E achei
primeiro que restringir o `P` separaria os servidores; quem separa é o caminho
da classe.
