# Capítulo 25 — Macro-checked interpolator

Minhas notas sobre o que cada exercício ensinou, escritas à medida que cada um
fechou (a partir de 2026-10-12).

## Exercício 01 — JSON, lido na compilação

| peça | ideia |
| --- | --- |
| `sc` é uma `Expr[StringContext]` | é o *código* `StringContext("[1, ", "]")`, não um valor com `.parts` |
| `'{ StringContext(${ Varargs(parts) }*) }` | a chamada é desmontada com um padrão citado; `Varargs` dá uma `Expr` por parte (`Seq[Expr[String]]`) |
| `valueOrAbort` em cada parte | cada parte é um literal, então o texto existe na compilação |
| `'{ Json.JBool(${ Expr(b) }) }` | `Expr(...)` leva um valor do compilador para o código; o quote monta a chamada em volta |
| não existe `ToExpr[Json]` | `Expr(JBool(b))` não compila; levar o `Boolean`, não o `Json` |
| `Expr.ofList` | `List[Expr[T]]` → `Expr[List[T]]`, o sentido contrário do `Varargs` |
| `build` no exercício, não no companion de `Tpl` | o parser é compartilhado e não sabe nada de macros; cada exercício monta de um jeito |
| `report.errorAndAbort(msg, expr)` no lugar de exceção | um `MatchError` numa macro aponta para o código da macro e não diz nada a quem chamou |
| `Position(pos.sourceFile, pos.start + offset, ...)` | a posição de uma parte começa no primeiro caractere dela, então o offset do parser vira um lugar no código |
| `case _` no `args match` | uma `Seq` pronta (`xs*`) não casa com `Varargs`; sem esse caso, `MatchError` dentro do compilador |

**Onde travei:** `$b` com `b: Boolean` — um splice recebe uma `Expr`. Achei
que `Expr.ofList` também separava; separar é com `Varargs`.

## Exercício 02 — argumentos, codificados pelo tipo

| peça | ideia |
| --- | --- |
| `Expr.summon[Encoder[w]]` | a busca roda *dentro da macro* e responde com um `Option`; no `None` nada é impresso, então a mensagem é minha (um `summon` deixado no código gerado daria a mensagem do compilador) |
| `'{ $encoder.encode(...) }` | a macro não conhece cada tipo; deixa no programa a chamada ao `Encoder` encontrado |
| `'{ $a: t }` | recupera o tipo de um argumento que chegou como `Expr[Any]` |
| `name.type`, `1` → `widen` | o tipo ligado é o *singleton* do argumento; `Encoder` é invariante, então `Encoder[Int]` não é um `Encoder[1]` |
| `.asType` + `case '[w]` | leva um `TypeRepr` (um valor) de volta a um tipo que dá para escrever entre colchetes |
| `a.asExprOf[w]` | `Expr[t]` para `Expr[w]`, conferido na compilação; seguro porque `t <: w` |

**Onde travei:** `Encoder.encode(n)` — o `encode` é de uma instância. E achei
que o `@implicitNotFound` do trait apareceria quando o `Expr.summon` não
achasse nada: a mesma lição do `summonFrom` no capítulo 24. Os erros
`no Encoder for name` / `no Encoder for 1` eram os tipos singleton aparecendo.

## Exercício 03 — o lugar do buraco decide o tipo

| peça | ideia |
| --- | --- |
| nenhum `Encoder` para chave | um `Encoder` produz `Json`, e a chave é a `String` do par `(String, Json)`: o argumento precisa já ser uma |
| `'{ $s: String } => s` | um padrão citado com tipo fixo só casa com uma expressão que cabe nele, e devolve uma `Expr[String]` |
| `${"id"}` sem `widen` aqui | o padrão testa subtipagem (`"id" <: String`); o `Expr.summon` procura o tipo exato, por isso o exercício 02 precisava |
| um segundo padrão, `'{ $a: t }`, para o erro | liga o tipo que a mensagem precisa citar |
| `TypeRepr.of[t].widen.show(using Printer.TypeReprShortCode)` | `Int`, não `n` (o singleton `n.type`, impresso curto) nem `scala.Int` |
| checado onde a chave está | o `key` nunca pede um `Encoder`, então uma chave `Instant` é reportada como chave, não como encoder ausente |

**Onde travei:** a mensagem citou primeiro as variáveis — `not n`, `not at` —,
o mesmo singleton do `no Encoder for name` do exercício 02.
