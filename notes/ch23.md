# Chapter 23 — Typed query builder

My notes on what each exercise taught. Reconstructed on 2026-10-13 from the
sessions of 2026-10-07 and 2026-10-08 (exercises 02 and 03) and, for
exercise 01, from the answer key's scaladoc.

## Exercise 01 — the row type from the columns *(from the answer key)*

| piece | idea |
| --- | --- |
| `Value[C] = C match { case Column[n, a] => a }` | one case, no fallback: anything else stays unreduced and is an error where used |
| `Values[Cs] = Tuple.Map[Cs, Value]` | the standard library's recursion over a tuple |
| `run: List[Values[Cs]]` | the row type is computed from the select, so it cannot drift |

## Exercise 02 — only this table's columns

| piece | idea |
| --- | --- |
| `where[N, A](column: Column[N, A])(value: A)` | `A` is already in the signature; no need for `Value[...]` |
| names cannot tell tables apart | `Users.id` and `Orders.id` share `N` and `A`; the path prefix is what differs |
| `<:<`, not `=:=` | a specific column *fits* `Column[?, ?]`, it is not *equal* to it |
| `Tuple.Union[Cs] <:< Column[?, ?]` | a union fits `T` only if every member does: "for every element" in one question |
| `select(EmptyTuple)` | the empty union is `Nothing`, which fits everything |

**Asked:** `=:=` vs `<:<` — use `=:=` when the type must *be* exactly that (a
boolean fact, a final state; `Nothing` must not slip through), `<:<` when it
only has to *fit*. And `trait` vs `abstract class` for `Table`: no difference
here, since Scala 3 traits take parameters; `abstract class` says "root of a
hierarchy".

## Exercise 03 — read a column from a row

| piece | idea |
| --- | --- |
| `IndexOf` with no `EmptyTuple` case | any "not found" number gets added to and becomes a valid position (my `-1` gave `1`); a stuck type does not |
| `IndexOf[...] <: Int` | `ops.int.+` only accepts what it knows is an `Int` |
| `ValueOf[IndexOf[Cs, Column[S, A]]]` | one piece of evidence does two jobs: exists only if the column is in the row, and its `.value` is the position |
| `(column: Column[S, A])` before the `using` | chapter 22's lesson again |
| search for `Column[S, A]`, not `S` | what is searched for must have the shape of the tuple's elements |
