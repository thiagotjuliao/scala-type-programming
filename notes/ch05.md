# Capítulo 05 — Opaque types & phantom newtypes

Minhas notas sobre o que cada exercício ensinou. Reconstruídas em 2026-10-13.
Este capítulo foi resolvido sem sessão de tutoria, então tudo aqui vem do
Scaladoc do gabarito.

## Exercício 01 — uma String por dentro, um Email por fora

| peça | ideia |
| --- | --- |
| `opaque type Email = String` | transparente dentro do seu escopo, sem relação com `String` fora dele |
| o único construtor valida | todo `Email` em qualquer outro lugar foi checado uma vez, aqui |
| o `type Email = String` do stub | um alias transparente *é* o tipo: uma extensão em `Email` vale para toda `String` |

## Exercício 02 — ler um Port como Int, nunca criar um a partir de um Int

| peça | ideia |
| --- | --- |
| `opaque type Port <: Int = Int` | o limite é público (um `Port` é um `Int`), a igualdade é privada (um `Int` não é um `Port`) |
| `Port.Http + 1` é um `Int` | correto: `Http + 70000` não é porta |

## Exercício 03 — só as chamadas que fazem sentido em cada estado

| peça | ideia |
| --- | --- |
| `Connection[S]` com os phantoms `Open` / `Closed` | o estado é um tipo que nenhum valor tem, apagado em runtime |
| extensões por estado, no companion | uma chamada no estado errado é um método que não existe, não uma checagem que falha |

## Exercício 04 — unidades que só existem na compilação

| peça | ideia |
| --- | --- |
| `opaque type Quantity[U] = Double` | opaco mais phantom: duas unidades são dois tipos, um único `double` em runtime |
| `+` só para o mesmo `U` | com um alias transparente, o `Double.+` ganha da extensão e nada é verificado |

**Depois (2026-10-05):** um merge da `main` depois de uma correção neste stub
apagou o meu `+` na resolução do conflito, e o módulo de testes inteiro parou
de compilar. Quando um stub já resolvido muda na `main`, manter o meu código e
