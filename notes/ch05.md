# Chapter 05 — Opaque types & phantom newtypes

My notes on what each exercise taught. Reconstructed on 2026-10-13. This
chapter was solved without a tutoring session, so everything here comes from
the answer key's scaladoc.

## Exercise 01 — a String on the inside, an Email on the outside

| piece | idea |
| --- | --- |
| `opaque type Email = String` | transparent inside its scope, unrelated to `String` outside |
| the only constructor validates | every `Email` anywhere else was checked once, here |
| the stub's `type Email = String` | a transparent alias *is* the type: an extension on `Email` lands on every `String` |

## Exercise 02 — read a Port as an Int, never make one from one

| piece | idea |
| --- | --- |
| `opaque type Port <: Int = Int` | the bound is public (a `Port` is an `Int`), the equation is private (an `Int` is not a `Port`) |
| `Port.Http + 1` is an `Int` | correct: `Http + 70000` is no port |

## Exercise 03 — only the calls that make sense in each state

| piece | idea |
| --- | --- |
| `Connection[S]` with phantom `Open` / `Closed` | the state is a type no value ever has, erased at runtime |
| extensions per state, in the companion | a call in the wrong state is a missing method, not a failed check |

## Exercise 04 — units that exist only at compile time

| piece | idea |
| --- | --- |
| `opaque type Quantity[U] = Double` | opaque plus phantom: two units are two types, one `double` at runtime |
| `+` only for the same `U` | with a transparent alias, `Double.+` wins over the extension and nothing is checked |
