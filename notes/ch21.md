# Capítulo 21 — Units of measure

Minhas notas sobre o que cada exercício ensinou. Reconstruídas em 2026-10-13 a
partir da sessão de 2026-10-05.

## Exercício 01 — multiplicar e dividir, e deixar o compilador calcular a unidade

| peça | ideia |
| --- | --- |
| `Mul` / `Div` como match type sobre duas tuplas de expoentes | a unidade é calculada com `compiletime.ops.int` |
| `type Mul[A <: Dim, B <: Dim] <: Dim = ...` | com `U` e `V` abstratos o match type não reduz, então o limite declarado do resultado é tudo o que o compilador sabe |

**Onde travei:** *"Type argument Mul[U, V] does not conform to upper bound
Dim"* — eu tinha limitado os parâmetros (o que entra), mas não o resultado (o
que sai).

## Exercício 02 — raiz quadrada, só onde a unidade tem uma

| peça | ideia |
| --- | --- |
| `N % 2 match { case 0 => N / 2 }` | uma condicional em tipos é um match type sobre um literal calculado com `ops`; não existe `If` pronto |
| o match type sozinho | nenhum caso casa → não reduz → **warning** (E184), não erro |
| `sqrt(using U =:= Mul[Half[U], Half[U]])` | a promessa da raiz pedida como evidência: é o que faz a chamada inválida falhar |

**Onde travei:** escrevi primeiro `r =:= Mul[Half[r], Half[r]]` — `r` é um
valor; os tipos a relacionar são `U` e `Half[U]`.

## Exercício 03 — fórmulas que o compilador confere

| peça | ideia |
| --- | --- |
| `Energy` como força × distância | outra grafia da mesma unidade reduz para a mesma tupla, então é o mesmo tipo |
| `sqrt(...)` chamado como função | uma extensão pode receber o receptor como argumento comum |
| fórmulas fora do `units` | dentro do escopo opaco `Quantity` é `Double`, e nada é verificado |
