## Exercise 01 — multiply and divide, and let the compiler work out the unit

| piece | idea |
| --- | --- |
| `Mul` / `Div` as a match type over two exponent tuples | the unit is computed with `compiletime.ops.int` |
| `type Mul[A <: Dim, B <: Dim] <: Dim = ...` | with abstract `U`, `V` the match type does not reduce, so the declared result bound is all the compiler knows |

**Stuck on:** *"Type argument Mul[U, V] does not conform to upper bound Dim"*
— I had bounded the parameters (what goes in) but not the result (what comes
out).

## Exercise 02 — a square root, only where the unit has one

| piece | idea |
| --- | --- |
| `N % 2 match { case 0 => N / 2 }` | a conditional on types is a match type over a literal computed with `ops`; there is no built-in `If` |
| the match type alone | no matching case → it does not reduce → a **warning** (E184), not an error |
| `sqrt(using U =:= Mul[Half[U], Half[U]])` | the promise of a square root asked as evidence: that is what makes the bad call fail |

**Stuck on:** I first wrote `r =:= Mul[Half[r], Half[r]]` — `r` is a value;
the types to relate are `U` and `Half[U]`.

## Exercise 03 — formulas the compiler checks

| piece | idea |
| --- | --- |
| `Energy` as force × distance | a different spelling of the same unit reduces to the same tuple, so it is the same type |
| `sqrt(...)` called as a function | an extension can take its receiver as an ordinary argument |
| formulas outside `units` | inside the opaque scope `Quantity` is `Double`, and nothing is checked |
