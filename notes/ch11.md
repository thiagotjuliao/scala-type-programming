# Chapter 11 — Evidence & type-safe state machines

My notes on what each exercise taught. Reconstructed on 2026-10-13 from the
short help on 2026-10-02 (exercises 03 and 04) and, for the rest, from the
answer key's scaladoc.

## Exercise 01 — methods for some stacks only *(from the answer key)*

| piece | idea |
| --- | --- |
| `sum(using Numeric[A])` | the method exists only where the fact can be proved |
| `flatten(using A <:< Stack[B])` | the evidence is also the conversion, so no cast in the body |

## Exercise 02 — chapter 06's JSON rules without a priority trick *(from the answer key)*

| piece | idea |
| --- | --- |
| `NotGiven[Numeric[A]]` as a premise | the rules become disjoint: at most one applies |
| the trap | `NotGiven` negates *the search succeeding*, so an ambiguous search also counts as absent |

## Exercise 03 — a builder that cannot be misused

| piece | idea |
| --- | --- |
| `Boolean` literal type parameters | the builder's state, erased at runtime |
| one type class per fact with `@implicitNotFound` | the error says what is missing, unlike *"Cannot prove that false =:= true"* |
| private constructor | `private` hides it from outside; the class body and the companion can still call it |

**Stuck on:** how to create the next builder when the constructor is private —
`private` is for outsiders only, so `url(u)` can call `new RequestBuilder(...)`.

## Exercise 04 — a door that only does what doors do

| piece | idea |
| --- | --- |
| `Next[S, E]` as a match type on `(S, E)` | the transition table, written once |
| catch-all to `Nowhere` | a state no door is ever in, to tell "has a row" from "has not" |
| `Allowed` derived with `NotGiven[Next[S, E] =:= Nowhere]` | the permission comes from the same table |
