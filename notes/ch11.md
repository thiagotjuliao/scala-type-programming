# Capítulo 11 — Evidence & type-safe state machines

Minhas notas sobre o que cada exercício ensinou. Reconstruídas em 2026-10-13 a
partir da ajuda rápida de 2026-10-02 (exercícios 03 e 04) e, para os outros,
do Scaladoc do gabarito.

## Exercício 01 — métodos só para algumas pilhas *(do gabarito)*

| peça | ideia |
| --- | --- |
| `sum(using Numeric[A])` | o método só existe onde o fato pode ser provado |
| `flatten(using A <:< Stack[B])` | a evidência também é a conversão, então não há cast no corpo |

## Exercício 02 — as regras de JSON do capítulo 06 sem truque de prioridade *(do gabarito)*

| peça | ideia |
| --- | --- |
| `NotGiven[Numeric[A]]` como premissa | as regras ficam disjuntas: no máximo uma se aplica |
| a armadilha | o `NotGiven` nega *o sucesso da busca*, então uma busca ambígua também conta como ausente |

## Exercício 03 — um builder que não dá para usar errado

| peça | ideia |
| --- | --- |
| parâmetros de tipo literal `Boolean` | o estado do builder, apagado em runtime |
| uma type class por fato com `@implicitNotFound` | o erro diz o que falta, ao contrário de *"Cannot prove that false =:= true"* |
| construtor privado | `private` esconde de quem está fora; o corpo da classe e o companion ainda podem chamá-lo |

**Onde travei:** como criar o próximo builder com o construtor privado —
`private` vale só para quem está fora, então o `url(u)` pode chamar
`new RequestBuilder(...)`.

## Exercício 04 — uma porta que só faz o que portas fazem

| peça | ideia |
| --- | --- |
| `Next[S, E]` como match type sobre `(S, E)` | a tabela de transições, escrita uma vez |
| catch-all para `Nowhere` | um estado em que nenhuma porta fica, para distinguir "tem linha" de "não tem" |
| `Allowed` derivado com `NotGiven[Next[S, E] =:= Nowhere]` | a permissão sai da mesma tabela |
