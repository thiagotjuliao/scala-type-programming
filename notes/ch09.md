## Exercício 01 — aritmética com números de Peano

| peça | ideia |
| --- | --- |
| `case (Succ[a], b) => Plus[a, Succ[b]]` | passar uma unidade de um lado para o outro mantém a soma: um acumulador |
| `Times`: `(a + 1) · b = b + a · b` | na multiplicação não há unidade para passar; recorrer com `Plus[b, Times[a, b]]` |
| `Succ[_0]` num padrão | um nome minúsculo ou começado por `_` num padrão é um *binder novo*, não o alias `_0` |

**Onde travei:** o meu `Times` dobrava em vez de somar: `Times[a, Plus[b, b]]`
diz `(a+1)·b = a·(2b)`, o que é falso. O jeito de depurar um match type
recursivo: escrever cada caso como uma igualdade e conferir se ela é
verdadeira. E `Succ[_0]` casava com todo sucessor, então o `ToInt` virava `1`
para tudo. Um bom caso de teste é `Times[_3, _2] =:= _6` — casos pequenos
escondem o dobro (2·1 = 1+1).

## Exercício 02 — a posição de um tipo numa tupla *(do gabarito)*

| peça | ideia |
| --- | --- |
| `case X *: _ => 0` | um nome maiúsculo no padrão é o parâmetro de tipo, não um binder |
| `Shift` em vez de `+ 1` | `IndexOf[t, X] + 1` transforma um `-1` em `0` |

## Exercício 03 — o `add` do capítulo 06, para tuplas de qualquer tamanho *(do gabarito)*

| peça | ideia |

## Exercício 04 — um vetor com o tamanho no tipo

| peça | ideia |
| --- | --- |
| `N + 1`, `N + M`, `N - 1` | tipos de `compiletime.ops.int`, reduzidos onde `N` é um literal |
| `def head(using N > 0 =:= true)` | a evidência na assinatura é resolvida em cada chamada, com o `N` concreto |
| uma prova positiva em vez de `NotGiven` | o `NotGiven` falha aberto: em código genérico, aceita; `N > 0 =:= true` falha fechado |

**Onde travei:** `summon[N =!= 0]` no corpo era resolvido uma única vez,
quando o `Vec` compilava, com `N` abstrato — e o `NotGiven` de um fato
desconhecido sempre vale.
