# Capítulo 10 — `Mirror` & generic derivation

Minhas notas sobre o que cada exercício ensinou. Reconstruídas em 2026-10-13 a
partir da sessão de 2026-10-01, a primeira feita pergunta por pergunta.

## Exercício 01 — o nome de um tipo e os nomes dos campos

| peça | ideia |
| --- | --- |
| `using m: Mirror.Of[T]` | o mirror chega com o refinamento, então `m.MirroredLabel` *é* `"Person"` |
| `constValue` / `constValueTuple` | um tipo literal, ou uma tupla deles, lido de volta como valor |
| `val m = summonInline[...]` | a quase-solução: o `val` tem o tipo declarado, e os membros voltam a ser abstratos |

**Aprendi:** com membros de tipo, pensar em tipos o máximo possível e só virar
valor no fim, e só o que for literal.

## Exercício 02 — `Show` para qualquer case class

| peça | ideia |
| --- | --- |
| valores dos campos | todo case class é um `Product`; `productIterator` dá os valores como `Any` |
| instâncias por campo | recursão inline sobre `MirroredElemTypes` com `erasedValue` |
| achar ou derivar | `summonFrom`: usa um `Show[H]` se houver, senão deriva pelo `Mirror.ProductOf[H]` |
| o cast | seguro porque a ordem é garantida; fica em `instances`, onde o tipo é esquecido, e o erasure o torna gratuito |
| inline só o necessário | o mirror é lido na expansão; a lógica de runtime fica num método comum |
| tipos recursivos | `elems` por nome, e um `lazy val` *fora* da lambda |

**Onde travei:** um `for` com três geradores é um produto cartesiano, e um
`Iterator` só pode ser lido uma vez — `lazyZip` anda pelas três listas lado a
lado. `Show` é invariante, não covariante: ele *consome* `A`, então a variância
correta seria `-A`. Uma anotação de tipo pede ao compilador que prove o tipo;
`asInstanceOf` é uma promessa que ele não confere.

## Exercício 03 — todos os valores de um enum

| peça | ideia |
| --- | --- |
| `SumOf` | `MirroredElemTypes` são os casos, na ordem de declaração |
| `ValueOf[T]` | vai de um tipo singleton ao seu único valor; `constValue` só cobre tipos literais |
| `error` | só aceita string literal — roda na compilação e não executa `s"..."` |
| o `h` de um padrão dentro de `summonFrom` | não age como o tipo concreto; passá-lo a um `inline def` com parâmetro de tipo próprio |

**Também:** o warning *"New anonymous class definition will be duplicated at
each inline site"* — tirei o `new Values[A]` para um método comum.

## Exercício 04 — uma case class a partir dos campos, e de volta

| peça | ideia |
| --- | --- |
| `build[T](using m: Mirror.ProductOf[T])(fields: m.MirroredElemTypes)` | um tipo só pode depender de um parâmetro *anterior*, então a cláusula `using` vem primeiro |
| `(...)` pula cláusulas `using` | uma lista de argumentos comum vai para a próxima lista comum |
| `Tuple` estende `Product` | `fromProduct` não precisa de cast |
| `Tuple.fromProductTyped` com `T <: Product` | elimina os dois casts do `fields` |
