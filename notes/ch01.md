# Chapter 01 — Type system foundations

My notes on what each exercise taught. Reconstructed on 2026-10-13: this
chapter was solved without a tutoring session (only a review afterwards, on
2026-09-23), so most of it comes from the answer key's scaladoc.

## Exercise 01 — annotate the variance

| piece | idea |
| --- | --- |
| `Source[+A]` | `A` only comes out (result types): covariant position |
| `Sink[-A]` | `A` only goes in (parameter types): contravariant position |
| `Channel[A]`, invariant | it both takes and gives `A`, so no variance is safe — the same reason `Array` has none |

## Exercise 02 — refine a trait's type members

| piece | idea |
| --- | --- |
| `Repo { type Id = Long; type Entity = Dog }` | a refinement fixes abstract members in the type itself, with no new trait |
| `DogRepo <: Repo` for free | a refinement is the same trait with more known about it, so it conforms wherever the plain one does |

## Exercise 03 — put the evidence to work

| piece | idea |
| --- | --- |
| `ev(a)` | `A =:= B` extends `A <:< B` extends `A => B`: the evidence *is* the conversion |
| `as.map(ev).sum` | the witness is a function, so it can be passed as one |
| no cast | only the compiler can create the evidence, and only when the types line up |

## Exercise 04 — a covariant stack

| piece | idea |
| --- | --- |
| `push[B >: A](b: B): Stack[B]` | a lower bound lets a covariant type accept a wider element by returning a wider stack, never by writing into itself |
| `Stack[Nothing]` as `empty` | with `+A`, one empty value serves every element type, like `Nil` |
