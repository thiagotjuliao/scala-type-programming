## Exercício 01 — anotar a variância

| peça | ideia |
| --- | --- |
| `Source[+A]` | `A` só sai (tipos de retorno): posição covariante |
| `Sink[-A]` | `A` só entra (tipos de parâmetro): posição contravariante |
| `Channel[A]`, invariante | recebe e entrega `A`, então nenhuma variância é segura — o mesmo motivo de `Array` não ter nenhuma |

## Exercício 02 — refinar os membros de tipo de um trait

| peça | ideia |
| --- | --- |
| `Repo { type Id = Long; type Entity = Dog }` | um refinamento fixa membros abstratos no próprio tipo, sem trait novo |
| `DogRepo <: Repo` de graça | o refinamento é o mesmo trait com mais informação, então serve onde o trait puro serve |

## Exercício 03 — pôr a evidência para trabalhar

| peça | ideia |
| --- | --- |
| `ev(a)` | `A =:= B` estende `A <:< B`, que estende `A => B`: a evidência *é* a conversão |
| `as.map(ev).sum` | a testemunha é uma função, então pode ser passada como uma |
| sem cast | só o compilador cria a evidência, e só quando os tipos batem |

## Exercício 04 — uma pilha covariante

| peça | ideia |
| --- | --- |
| `push[B >: A](b: B): Stack[B]` | um limite inferior deixa um tipo covariante aceitar um elemento mais largo devolvendo uma pilha mais larga, sem nunca escrever em si mesmo |
| `Stack[Nothing]` como `empty` | com `+A`, um único valor vazio serve para todo tipo de elemento, como o `Nil` |
